# ①課題名
Find Your Favorite Movie

## ②課題内容（どんな作品か）
- 映画のタイトルを入れると、概要、配信、パッケージ、図書館の情報が得られる。
- TMDb API（映画情報の総合取得）、Google Books API（ISBN取得）、カーリルAPI（図書館蔵書・在庫の照会）という3つのAPIを使用。

## ③アプリのデプロイURL
デプロイしている場合はURLを記入（任意）

## ④アプリのログイン用IDまたはPassword（ある場合）

## ⑤工夫した点・こだわった点
- 映画のタイトルから複数のメディアの情報を得られるようにした。
- 多数のAPIや連携方法があるなかで、自分の技術の範囲内で扱えるAPIを採用。
- デザインはアカデミー賞っぽいイメージに。

## ⑥難しかった点・次回トライしたいこと（又は機能）
- 難しかった。構想では、映画タイトル入力→概要、配信情報、パッケージ情報、原作情報が一括で得られるアプリにしたかったのに、概要以外は思ったものを作れなかったです（今後の課題）。
- ベースとなるTMDb APIと、カーリルAPIの採用はすぐに決まった。配信関連のAPIではWatchmode APIがあるが、Geminiに「単にURLを生成するだけでなく、APIが返すJSONデータから「現在地（日本）で視聴可能なプラン（SVODかTVODか）」をフィルタリングする複雑なロジックが必要」と言われ、課題提出までに学びながら実装する自信がなく、今回は配信関連はAPIではなく検索方式を採用。
- TMDbから呼び出した情報をカーリルにつなぐために、ISBNの情報が必要になったため、テストAPIキーが公開されているRakutenの使用を試みたが、うまく動かず、Google Books APIに変更。
- カーリルは検索に時間がかかり、1回のリクエストで即答できないことから、ポーリングという仕組みを採用。「ISBN取得」と「在庫確認」を分けて管理する仕組みになっている。

## ⑦フリー項目（感想、シェアしたいこと等なんでも）
- APIの説明文やキー取得のために入力すべき項目の意味が分からず、AIに質問しながら進めたので大変だった―という印象です。また、安全のために公開してはいけない情報、設定時に外しておくべきチェック項目などが十分に咀嚼できていない自信がありますｗ
- APIを使ったというよりも、深淵なる世界の入り口がようやく見えたくらいの感覚です。
